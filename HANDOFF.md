# sbe-offers — передача в новое контекстное окно

Обновлено **2026-11-06**, **версия 0.7.5**: при печати по макету .docx ссылки
стали кликабельными, текст идёт одним конвейером (верхние индексы, списки,
заголовки), появилась метка картинки. Остальные записи — история предыдущих
выпусков.

**Начинаете со свежим контекстом — читайте раздел «Текущее состояние» ниже.**

## Что вошло в 0.7.5 (живой КП 003/2026 (2).docx, 2026-11-06)

**Жалоба пользователя:** текст не читается как цельное технико-рекламное
произведение, система не вставила изображения, текст рваный, скил не
применяется, нет верхних индексов для м², ссылки не активные, одна ссылка
отсутствует, ответ модели не соответствует промту.

**Скил применялся** — промпт `RenderBlockSystem` доходил до модели. Не
применялось всё остальное: печать по макету шла своим путём и делала четверть
того, что делал блочный путь. Отсюда все жалобы разом.

### Причины

| Симптом | Причина |
|---|---|
| ссылки не кликабельны | в `docx_layout.go` НЕ БЫЛО ни `applyHyperlinks`, ни `relsXMLWithLinks` — при загруженном макете ссылка не могла стать ссылкой ни при каком ответе |
| одна ссылка отсутствует | её выбросила чистка: `hasReasoningLine` считал строку-адрес английским рассуждением, а `trimTruncatedTail` резал по точкам в `nav.tn.ru` и превращал строку в «Технический лист.» |
| нет верхних индексов | `layoutAsParagraphs` писал `<w:t>` через `escapeXML` в обход `plainText`+`runsXML`; в таблице ² были, потому что таблицу строит `tableXML` блочного пути |
| текст рваный | заголовки модели печатались телом: механизма «сделать абзац заголовком» в печати по макету не было |
| нет изображений | метки картинки не существовало; у промта один выход — текст |

## Что вошло в 0.7.4 (живой КП 003/2026, 2026-11-06)

### Причина — три дефекта, все жили в коде одновременно

1. **Метка вёрстки гасила весь блок.** В `form_values` КП 003/2026 лежал ответ
   модели (`gen.layout.46f1df42…`, 1967 знаков), и он был **черновиком**:
   ```
   1. "Гидроизоляция фундамента: одна система на горизонталь, вертикаль и отмостку".
   Заголовок: "Система ТН-ФУНДАМЕНТ Дренаж Проф закрывает весь подземный контур дома"
   Текст: задача объекта — новый многоквартирный дом …
   ```
   `reReasoningHeadingMarker` видел строку `Заголовок: …`, `looksLikePlan`
   возвращал `true`, `cleanBlockText` отдавал `""` — и в кэш писалась пустая
   строка. Правило «есть хоть одна метка → весь ответ план» убивало весь текст
   из-за одной строки.

2. **Свой `max_tokens` обрезал ответ.** `blockMaxTokens(666)` = 7260 токенов —
   модель не укладывалась, ответ кончался на полуслове, и в `content` оставалось
   то, что она сказала ДО ответа (рассуждение). Плагин 007 этого не знает,
   потому что `max_tokens` не шлёт вовсе (`llm-center.ts:239-246`).

3. **Не было повтора.** Один медленный ответ = пустой блок. У 007 есть
   `retryWithBackoff` на 3 попытки.

### Что изменено

- **`docx_text.go`** — судьба одной строки решается в одном месте
  (`cleanDraftLine` → `withoutLayoutMarker` / `isDraftSentence` /
  `cutReasoningTail`). Метка вёрстки снимается как ПРЕФИКС, текст за ней
  печатается; выбрасывается только сирота-метка («Цена», «Ссылки (Heading 1)»).
  `looksLikePlan` сравнивает число строк-оглавления с числом настоящих строк
  (`outline > prose`), а не «есть хоть одна».
  `documentTextMaxTokens()` возвращает **0** — предел даёт провайдер
  (`buildChatBody` не кладёт `max_tokens` при нуле).
- **`docx_layout.go`** — печать макета просит текст с тем же нулём.
- **`llmclient.go`** — `llmOnce` (один запрос) + цикл из `llmRetryAttempts` = 3
  с паузой `llmRetryBackoff`. `llmRetryable`: таймаут, 502, 504, 429, обрыв
  связи — повторяем; «ключа нет» и 400 — нет.
- **`src/main.ts`** — текст новости ЦУП переписан под 0.7.4.

## Что вошло в 0.7.3 (живой КП 003/2026, 2026-11-06)

Работа велась НЕ «по коду», а прогоном настоящего промпта сервиса на живой
модели с данными боевого КП (pull из `mailers-offers-db-1`), внутри
`golang:1.24` на docker-сети `mailers_internal`. Так найдено шесть дефектов,
которые ни один юнит-тест не показывал.

1. **Промт, разбитый на несколько абзацев Word, не находился ВООБЩЕ.**
   В макете `temple.docx` инструкция описания — девять абзацев: `{{` в первом,
   `}}` в девятом. Разбор шёл ПО АБЗАЦУ (`reWordParagraph`), и метка не
   находилась ни в одном из них — все девять абзацев инструкции уходили
   клиенту литералом. Теперь `fillLayoutDocument` ищет метки по СКЛЕЙКЕ всего
   тела документа (`paragraphSpans`), а подстановка раскладывается по абзацам
   (`replaceInSpan` → `paragraphChange`). Требование «промт одним блоком» из
   этой ошибки и выросло: писать одним абзацем не нужно, система обязана
   понимать и многоабзацный.

2. **Склейка без разделителей портила инструкцию.** Сразу после починки
   модель получала «…входящих в состав решения;- преимущества…» и
   «…технического решенияОписания найди в базе знаний…» — пункты списка
   слипались, слова склеивались. Теперь абзацы склеиваются ЧЕРЕЗ ПЕРЕНОС
   СТРОКИ, а метка чистит текст через `normalizePromptText`
   (`layout_tokens.go`): пункт списка (`- `, `1. `) остаётся своей строкой,
   обычный абзац продолжает предыдущий через пробел.

3. **Таблица не печаталась вовсе.** Промт просил таблицу, а общий промпт
   ЗАПРЕЩАЛ списки и таблицы — модель металась и отдавала прозу. Теперь:
   - `tableDoc` (`skills/prompt.go`) разрешает таблицу и просит markdown;
   - `splitAnswerTables` + `tableXML` печатают её настоящим `<w:tbl>`;
   - **метка-таблица вообще не ходит в модель**: `layoutTableFor` собирает
     строки из данных предложения — позиции для «предложения по материалам»
     (`layoutOfferTable`), характеристики карточек для «сравнения вариантов»
     (`layoutCompareTable` → `compareSystemRows`). Вид определяется по тексту
     инструкции (`layoutTableKindOf`), «сравнение» проверяется первым.

4. **Ячейка с переводом строки рвала таблицу на куски.** В живом КП названия
   утеплителей содержат `\n` («Утеплитель ХPS Carbon Prof 100 мм, на глубину
   промерзания)»). Markdown-строка не может содержать `\n`: 41 позиция давала
   **5 таблиц** вместо одной. `tableCell` сводит ячейку в одну строку.

5. **Черновик модели попадал в документ.** Модель отвечала планом
   («2. h2 \"Состав решения\"…»), описанием вёрстки («Heading 2: …»,
   «Ссылки (Heading 1)»), рассуждением («Задача: …», «Хм…») и вопросами к
   себе («ЕКН — артикул?»). Добавлены `reReasoningHeadingMarker`,
   `reHeadingWord`, `reSelfQuestion`, `rePlanMarker` и `looksLikePlan`.
   **Признак плана — только служебные маркеры вёрстки** (решение
   пользователя): нумерованный список сам по себе планом НЕ считается, потому
   что состав конструкции в КП — это честный нумерованный список слоёв.
   Если план распознан — блок молчит (пустой блок честнее оглавления).

6. **Объём ответа брался не из подсказки.** Макет просит «Объем текста не
   менее 4000 знаков на одну систему», а бюджет оставался `genDefaultMaxWords`
   = 150 слов. `skills.RequestedWords` читает объём из инструкции (знаки → /6,
   предел 800 слов).

### И главное: почему модель «отвечала рассуждением»

**Таймаут 45 с.** `llmDefaultTimeoutMS` в `llmclient.go` был 45000 мс, а ответ
на 4000 знаков модель пишет **58 секунд** (замерено). Клиент обрывал запрос, и
в документ шло то, что модель успела сказать ДО ответа. Поднято до 180000 мс —
провайдер держит запрос до 190 с (`doProviderRequest` в llm-service).

### Подмена модели — проверено, её нет

Подозрение было: в базе `deepseek-v4.1-flash`, а модель отвечает «я ChatGPT».
Проверено четырьмя способами, **подмены нет**:

- наш сервис уходит с `model="deepseek-v4.1-flash"` (логирование в
  `internal.go`, снято после проверки);
- провайдер имя ПРИНИМАЕТ, в ответе пишет `"model":"deepseek-v4.1-flash"`, а
  несуществующее имя отклоняет с 400 — «подставить первую из списка» не может;
- в каталоге провайдера (`GET /api/v1/models`, 93 модели) `deepseek-v4.1-flash`
  есть, `owned_by=deepseek`, `is_old_model=false`;

## Правила, которые нельзя нарушать

Полный список — `sbe-offers/AGENTS.md`, «Rules» и «Gotchas». Самые дорогие:

- `\b` в регулярках по кириллице **не работает** — границу задавать явно.
- Кириллица в собранном `main.js` — `\uXXXX` **верхним** регистром. Проверять
  только `node scripts/check_bundle_strings.mjs`.
- Источники править только редактором. Перезапись через PowerShell-пайплайн
  превращает файл в мусор (логотип инцидента: `jsonrepair.go` → `Р Р°Р·Р±РѕСЂ`).
- Файлы писать UTF-8 **без BOM**; после правки проверять первые три байта.
- **`git show … | Set-Content` и любой пайплайн PowerShell над текстом** на
  этой машине периодически отдают **0 байт / пустые строки** (наблюдалось
  2026-11-02 на `AGENTS.md` и `offers_local_e2e.mjs`). Проверять результат
  через `python -c "len(open(...).read())"`, а перед коммитом — `git diff`.
- Время в API — `RFC3339Nano`; любая запись в БД двигает `updated_at`.
- Стенд собирать с `CGO_ENABLED=0`; бинарь подменять только после сборки.
- **Экран не ходит в чужой сервис на каждый показ** — кеш + явная кнопка.
- Коммит/пуш/деплой/выкладка — только по явной команде пользователя, на одну
  партию. «Продолжай», «ок» — не команда фиксировать.

offers_context where mode='systems'"`, затем `docker restart
offers-local-kb-stub` (иначе раздел «Системы» отдаст старое и стенд будет
проверять прошлую заглушку). Так было дважды: 2026-11-02 и 2026-11-05.

**Образы стенда, если Docker Hub недоступен** (на этой машине так бывает —
`TLS handshake timeout`): тянуть через зеркало и переименовывать.

```
docker pull mirror.gcr.io/library/postgres:16-alpine
docker pull mirror.gcr.io/library/node:22-alpine
docker pull mirror.gcr.io/library/golang:1.24
docker tag mirror.gcr.io/library/postgres:16-alpine postgres:16-alpine
docker tag mirror.gcr.io/library/node:22-alpine node:22-alpine
docker tag mirror.gcr.io/library/golang:1.24 golang:1.24
```

**Стенд обновить после правок сервиса.** Удобнее пересобрать образ и
пересоздать контейнер — `docker compose build offers` + `docker rm -f
offers-local-app` + `docker compose -f docker-compose.local.yml up -d offers`.
**`up -d` без `rm -f` контейнер не пересоздаёт** (проверяйте `CREATED` в
`docker ps`, а не слово `Started` в выводе compose) — на этом потерялся
прогон 2026-11-05.

Если контейнеры `offers-local-*` остались от прошлого прогона и ругаются на
занятые имена — `docker rm -f` их всех, затем `docker compose -f
docker-compose.local.yml up -d` (не `--force-recreate`: он тоже упирается в
конфликт имён).

Состояние на **2026-11-05**: **0.6.0 выпущена полностью** — обе ветки
запушены, плагин на самораздаче, сервис и бот задеплоены и проверены.

документе), B (бриф доходит до модели), C (несколько систем и сравнение) — это
выпуски 0.5.1 и 0.6.0. Следующие шаги — макет `.docx` и повторяемый блок «по
системам» (см. выше).
