## Что за плагин

**LogicTEAM.КП** (`sbe-offers`) — коммерческие предложения для отдела продаж:
каталог систем и материалов, конфигуратор формы КП, сборка предложения в
Telegram-боте и в самом Obsidian, на выходе — DOCX на фирменном бланке.
Каталог и форму настраивает администратор; менеджеры работают в боте.

Вольт: `C:\Obsidian\mailers`. Папка плагина: `.obsidian/plugins/sbe-offers`.
Оба серверных кода — в **этой же** папке: `offers-service/` (Go) и
`offers-bot/` (Node). Рабочая ветка — `backend`; `main` — релизный срез без
бэкендов.

### Что умеет сейчас

- **Материалы** — то, что продаём: свой SKU (назначает сервер), варианты ЕКН,
  вилка цен. **Цены в справочнике нет** — цена приходит из таблицы менеджера.
- **Системы** — карточки БЗ с тегом `commercial_propose` без `material`.
  Состав ссылается на материалы вики-ссылками `[[Название]]`; строки без
  ссылки и без кода — слои и работы, а не ошибки. Раздел показывает **кеш**;
  перечитать — «↻ Перечитать из Базы знаний». В одном КП систем может быть
  несколько (`Offer.systems`, порядок выбора).
- **Бот** — «Собрать КП» начинается с контекста (объект → адресат → сделка →
  системы → условия → позиции). Файл принимается на любом шаге.
- **Форма КП** — блоки: текст, заголовок, список, таблица, разрыв страницы,
  ссылки, текст по промту, картинка с обтеканием, сравнение систем; повторы
  «по каждой системе» и «по каждой позиции»; размещение (отступы, «с новой
  страницы», «не разрывать»). Загруженный `.docx`-макет вытесняет блоки.
- **Документ** — по блоку формы **или** по макету `.docx`; тексты систем
  берутся из `offers_system_text` (кэш, без вызова модели при экспорте);
  каждая система — своё описание, свои преимущества, своя нумерация слоёв с 1;
  вступление описывает **все** выбранные системы, а раздел «выбрано» в промпте
  называет каждую систему **названием из карточки** (0.9.2), а не «система №N.
- **Боевой листок (0.9.0, 2026-11-08)** — быстрая справка-сравнение нашего
  продукта (систем из КП) с продуктами конкурентов. Отдельная вкладка в
  сайдбаре («Боевой листок»), свой список и карточка. Наш продукт — из систем;
  конкурент — из папки Базы знаний «материалы и системы конкурентов» (кеш +
  «↻ Перечитать», раздел «Конкуренты», admin). Своя форма — **тот же
  конфигуратор, что у КП**, под режимом `combat` (`offers_form.mode='combat'`).
  Кнопка «Форма КП» переехала внутрь раздела КП (рядом с «Новое предложение»).
  Готовый листок **выгружается в DOCX** (кнопка «⬇ DOCX»): печать по форме
combat, обе стороны сравнения — карточками. **В боте (0.9.1, 2026-11-09):**

## Правила, которые нельзя нарушать

Полный список — `sbe-offers/AGENTS.md`, разделы «Rules» и «Gotchas». Самые
дорогие:

- `\b` в регулярках по кириллице **не работает** — границу задавать явно.
- Кириллица в собранном `main.js` — `\uXXXX` **верхним** регистром. Проверять
  только `node scripts/check_bundle_strings.mjs`.
- Источники править только редактором. Перезапись через PowerShell-пайплайн
  превращает файл в мусор.
- Файлы писать UTF-8 **без BOM**; после правки проверять первые три байта.
- Время в API — `RFC3339Nano`; любая запись в БД двигает `updated_at`.
- Стенд собирать с `CGO_ENABLED=0`; бинарь подменять только после сборки.
- **Экран не ходит в чужой сервис на каждый показ** — кеш + явная кнопка.
- **Кэш текста ключуется по всему, что видел модель**: данные КП, набор
  систем, карточка. Иначе текст молча замерзает.
- Коммит/пуш/деплой/выкладка — только по явной команде пользователя, на одну
  партию. «Продолжай», «ок» — не команда фиксировать.

## Как выкладывать выпуск

Порядок проверен на 0.7.6 … 0.8.2; подробности и грабли — в архиве.

1. **Версия и новость.** Поднять номер в `manifest.json` и `package.json`,
   **переписать текст новости ЦУП** в `src/main.ts` (`announceOnce`) и
   строки-иглы в `scripts/check_bundle_strings.mjs`, затем `npm run build`.
2. **Проверки** — полный прогон выше.
3. **Коммиты** на `backend` (сервис / стенд / выпуск — по смыслу) и пуш.
4. **Перенос на `main`**: `git checkout main`, `git checkout <release> -- main.js
   manifest.json styles.css src scripts package.json AGENTS.md HANDOFF.md`,
   `tsc`, коммит, пуш. Серверные папки в `main` **не переносятся**.
5. **Деплой**: `git archive --format=tar <release> offers-service offers-bot` →
   `scp` → `tar xf` в `/opt/mailers` → **сверить `md5sum` ДО сборки** →
   `docker compose build` → `up -d --force-recreate` → health `ok`, поллер.
6. **Самораздача**: `scp` трёх файлов в `/tmp/selfhost-upload/sbe-offers/`,
   сверить `sha256sum`, `kb-selfhost.sh sbe-offers`, затем скачать три файла по
   https и сверить суммы ещё раз.
7. **Реестр**: `www/registry.json` на сервере поправить **точечно по ключу**
   (`version`, `uploadedAt`, три суммы) — скрипт пишет только суммы. Затем
   git-копия `sbe-apstore-registry`, коммит и пуш.
8. **Документация**: `AGENTS.md` и `HANDOFF.md` — блок выпуска с хэшами;
   корневой `plugins/AGENTS.md` — строка таблицы версий; `check_docs_state`.

**Доступ к серверу:** алиас `epyur` из `~/.ssh/config` (ключ
`id_ed25519_20261103`); `scp`/`ssh` на голый адрес `root@176.12.69.109` даёт
`Permission denied (publickey)`.
