приходит с CRLF**, и последний аргумент строки получает `\r` — `head -5`,
`cat /tmp/x`, `-c "…"` падают с «No such file» / «invalid option», причём
выглядит как «файла нет». Для многострочных проверок писать скрипт файлом
(локально `write` → `scp` → `sh /tmp/x.sh`), а не гнать строки через stdin.
Первый признак — команда выполнилась, а следующий `grep`/`cat` «не видит» файл,
который только что создан.

## ОТКРЫТЫЕ ДЕФЕКТЫ БОЕВОГО ЛИСТКА — ревизия 2026-11-17 (код не менялся)

Пользователь: «противоречие не устранено… ссылки на документы из базы документов
(иные документы в заметке нашего продукта) не добавлены… в настройках плагина не
появилось базового промта… нужно окно формы боевого листка убрать всё лишнее».
Ревизия кода против ТЗ и план — `C:\Obsidian\mailers\docs\superpowers\plans\2026-11-17-sbe-offers-combat-revision-plan.md`.

Что нашлось (факты, не предположения):

1. **Окна формы боевого листка в UI нет** — в разделе листка только «📄 Макет
   боевого листка» (`combat-view.ts:98`); редактор формы вызывается только в
   режиме КП, значит путь `mode='combat'` в `form-editor.ts` **мёртвый**.
   Поэтому базовый промт листка нигде не виден: он рисуется только в этом
   мёртвом пути (в редакторе КП группа «Базовый промт документа» есть).
2. **Карточка макета листка показывает КП-шное**: полный список меток КП и
   «⬇ Скачать образец макета» — это образец **КП** (`образец-макета-КП.docx`);
   у листка одна метка — `{{сравнение}}`.
3. **Список листков — таблица** «Номер | Название | Наш продукт | Конкуренты |
   Статус | Менеджер» (из 0.9.0) — пользователь считает это лишним.
4. **Раздел `## Иные документы` не читается.** Ссылки собирает `ParseCardRefs`
   только из «## Ссылки» (+ `LinkedRefs` материалов). На живом примере (заметка
   6363): «## Иные документы» несёт markdown-ссылки на файлы приложения
   «Документы» (`/api/documents/file?key=…`, с `<!-- kb-doc:… -->`); также не
   читаются вложения `![[…pdf]]` и wiki-ссылки `[[СТО …]]` (`note_links`).
5. **Противоречие в тексте живо и объяснимо**: подразделы пишутся независимыми
   вызовами модели и друг друга не видят; при пустом `base_prompt` ключ кэша
   не меняется, поэтому старый текст («равноценны») остаётся; сам базовый промт
   по умолчанию в 0.11.5 не менялся.
6. **ТЗ расходится с кодом**: `specification.md` §«Боевой листок: как он
   устроен» говорит «формы у листка нет, настраивается только макет, единственное
   поле — `hint`», а с 0.11.4 у листка работают разделы формы и тексты
   кэшируются в `form_values`.

вверху файла): у листка есть своё окно «⚙️ Настройки боевого листка» (промт,
ссылки, макет), карточка макета в режиме `combat` больше не показывает метки КП

**Решения, принятые 2026-11-17** (вопросы плана §5): разделы листка остаются
заготовкой в коде, окна у них нет; окно промта — своё окно «Настройки боевого

- **`scp` текстового файла со списком md5 тоже портит содержимое** тем же
  путём: содержимое читалось байтами и уже без `r`. Сверять надо **сам

## Как выкладывать выпуск

Порядок проверен на 0.9.20 (полный цикл 2026-11-13), повторён на 0.9.23
(2026-11-14) и на 0.9.27 (2026-11-14, выкладывалось только ПРИЛОЖЕНИЕ:
шаги 1-3, пуш приложения из шага 6, шаги 7-9; шаги 4-5 — срез и деплой бэка —
выполнены без пересборки контейнеров).

**Грабли самого процесса (проверено на 0.9.23):**
- `<<'MSG'` (heredoc) в PowerShell **не работает** — сообщение писать в файл и
  `git commit -F <file>`.
- Вывод `ssh … > файл` на этой машине пишется **UTF-16LE**: сравнение `md5sum`
  прочитает мусор. Читать с `utf16le`, либо сверять скриптом на сервере.
- `kb-selfhost.sh` пишет `hashes` в **БД**; `www/registry.json` может нести
  старые — `/registry.json` отдаёт значения из БД, это норма. `version` в файле
  всё равно правится (бэкап `registry.json.bak-<дата>` рядом).

1. **Версия и новость.** Поднять номер в `manifest.json` и `package.json`,
   **переписать текст новости ЦУП** в `src/main.ts` (`announceOnce`) и иглу в
   `scripts/check_bundle_strings.mjs`, затем `npm run build`.
2. **Проверки** — полный прогон выше (включая стенд).
3. **Коммит на `backend`** и пуш.
4. **Перенос на `main`**: `git checkout main`,
   `git checkout <backend-sha> -- main.js manifest.json package.json styles.css src scripts AGENTS.md HANDOFF.md specification.md`,
   `tsc`, `build` (должен совпасть байт в байт с backend-сборкой), коммит, пуш.
   Серверные папки (`offers-service/`, `offers-bot/`) и `offers-app/` в `main`
   **не переносятся**. Ветку `backend` держать чекаутнутой дальше.
   ⚠️ `offers-app/` не отслеживается на `main` — `git add -A` затянет его в
   коммит. Проверять `git status` до коммита; если затянуло — `git reset --soft
   HEAD~1` и `git rm -r --cached offers-app`.
5. **Деплой**: `git archive --format=tar --prefix=offers-XXXX/ -o <file> <sha> offers-service offers-bot`
   → `scp` → `tar xf` в `/tmp` → `cp -a` папки бэка в `*.bak-<дата>` →
   `rsync -a --delete` в `/opt/mailers/` → **сверить `md5sum` ДО сборки**
   (расхождение в `.ts` бывает только по CRLF — сверять после нормализации)

## Правила, которые нельзя нарушать

Полный список — `sbe-offers/AGENTS.md`, разделы «Rules» и «Gotchas». Самые
дорогие:

- `\b` в регулярках по кириллице **не работает** — границу задавать явно.
- Кириллица в собранном `main.js` — `\uXXXX` **верхним** регистром. Проверять
  только `node scripts/check_bundle_strings.mjs`.
- Источники править только редактором. Перезапись через PowerShell-пайплайн
  превращает файл в мусор.
- Файлы писать UTF-8 **без BOM**; после правки проверять первые три байта.
- Время в API — `RFC3339Nano`; любая запись в БД двигает `updated_at`.
- Стенд собирать с `CGO_ENABLED=0`; бинарь подменять только после сборки.
- **Экран не ходит в чужой сервис на каждый показ** — кеш + явная кнопка.
- **Кэш текста ключуется по всему, что видел модель**: данные КП, набор
  систем, карточка. Иначе текст молча замерзает.
- Коммит/пуш/деплой/выкладка — только по явной команде пользователя, на одну
  партию. «Продолжай», «ок» — не команда фиксировать.
