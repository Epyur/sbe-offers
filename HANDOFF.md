## Что в 0.9.20 (2026-11-13, R2): одна кнопка «Создать новый документ»

В меню вместо «🧾 Собрать КП» и «⚔️ Боевой листок» — одна кнопка
**«✨ Создать новый документ»**. Бот спрашивает вид (КП / листок), затем первым
делом — дословно по заявке — **«Какой продукт или систему вы хотите предложить
покупателю?»**. Название уходит в поиск по Базе знаний (`/bot/suggest`), найдённое
показывается нумерованным списком; номера — кнопки. Ничего не нашлось — не тупик:
«уточнить название» рядом с «выбрать в приложении». После выбора — развилка
**«📚 Собрать контекст в чате»** (существующий бриф) или **«📱 Продолжить в
приложении»** (создаётся строка документа, продукт записывается, ответ несёт
инлайновую `web_app`-кнопку на `#/offer/{id}` / `#/sheet/{id}`).

Старые подписи «Собрать КП» и «Боевой листок» остались **псевдонимами** в

### Грабли этого захода (чтобы не повторять)

- **Стенд запускается всегда, Docker на машине работает.** Записи «Docker не
  запускался» в старых блоках этого файла относятся к прошлым дням. Команда с
  монтированием бота — в разделе «Проверки» ниже (`BOT_DIR`, `OFFERS_BOT_URL`).
- **`parseCallbackData` и составной префикс.** `nd:pick:3` разбирается по
  ПОСЛЕДНЕМУ двоеточию; разбор по первому даёт `Number('pick:3')` = `NaN` и
  молчаливое «нажал — ничего не произошло». Сторож — `callbacks-data.test.ts`.
- **Текст в новом диалоге проверяется РАНЬШЕ листка и черновика**
  (`handleNewDocText` до `isCombat`/`handleDraftText`), иначе название продукта
  стало бы позицией с ценой 0.
- **`git checkout <branch> -- ...` не годится для `offers-app/`**: каталог
  не отслеживается на `main` и молча уезжает в коммит. Проверять
  `git status` перед коммитом на `main`.
- **`uploadedAt` в `/registry.json` берётся из БД** (`registry_file_overrides`),
  а не из git-копии: скрипт `kb-selfhost.sh` пишет его сам. Git-копию правят
  ровно этим же значением, иначе два источника расходятся.
- **CRLF при переносе на сервер:** md5 локальных `.ts` и на сервере может
  отличаться — это только переводы строк. Сверять ПОСЛЕ нормализации
  (`\r\n` → `\n`), иначе полдня уходит на поиск несуществующей разницы.
- **`ssh '... while read ...'` съедает stdin** (того же класса, что известная
  грабля с `docker exec -i`). Для списка файлов — `find -print0 | xargs -0`.

## Как выкладывать выпуск

Порядок проверен на 0.9.20 (полный цикл 2026-11-13).

1. **Версия и новость.** Поднять номер в `manifest.json` и `package.json`,
   **переписать текст новости ЦУП** в `src/main.ts` (`announceOnce`) и иглу в
   `scripts/check_bundle_strings.mjs`, затем `npm run build`.
2. **Проверки** — полный прогон выше (включая стенд).
3. **Коммит на `backend`** и пуш.
4. **Перенос на `main`**: `git checkout main`,
   `git checkout <backend-sha> -- main.js manifest.json package.json styles.css src scripts AGENTS.md HANDOFF.md specification.md`,
   `tsc`, `build` (должен совпасть байт в байт с backend-сборкой), коммит, пуш.
   Серверные папки (`offers-service/`, `offers-bot/`) и `offers-app/` в `main`
   **не переносятся**. Ветку `backend` держать чекаутнутой дальше.
   ⚠️ `offers-app/` не отслеживается на `main` — `git add -A` затянет его в
   коммит. Проверять `git status` до коммита; если затянуло — `git reset --soft
   HEAD~1` и `git rm -r --cached offers-app`.
5. **Деплой**: `git archive --format=tar --prefix=offers-XXXX/ -o <file> <sha> offers-service offers-bot`
   → `scp` → `tar xf` в `/tmp` → `cp -a` папки бэка в `*.bak-<дата>` →
   `rsync -a --delete` в `/opt/mailers/` → **сверить `md5sum` ДО сборки**
   (расхождение в `.ts` бывает только по CRLF — сверять после нормализации)
   → `docker compose build offers offers-bot` → `up -d --force-recreate` →
   health `ok`, поллер запущен. Менялся только плагин/бот — `offers` не трогать.
6. **Приложение**: `scp` файлов `offers-app/dist/` на сервер → сверить
   `sha256sum` → заменить в `/opt/mailers/www/app-offers/` (`rm` старых
   `assets/*.js`, имя хэшированное) → скачать по https и сверить ещё раз.
7. **Самораздача**: `scp` трёх файлов в `/tmp/selfhost-upload/sbe-offers/`,
   сверить `sha256sum`, `sh /opt/mailers/kb-selfhost.sh sbe-offers`, затем
   скачать три файла по https и сверить суммы.
8. **Реестр**: скрипт пишет только `hashes` и `uploaded_at` в БД. `version`
   правится точечно в `www/registry.json` на сервере (бэкап рядом) — и **та же
   строка `version`** в git-копии `sbe-apstore-registry`, коммит и пуш.
   `uploadedAt` в git-копию переносится **значением из `/registry.json`**
   (он берётся из БД, а не из файла).
9. **Документация**: этот файл (блок выпуска с хэшами), `AGENTS.md`,
   корневой `plugins/AGENTS.md` — строка таблицы версий.

**Доступ к серверу:** алиас `epyur` из `~/.ssh/config` (ключ
`id_ed25519_20261103`).

Полный список — `sbe-offers/AGENTS.md`, разделы «Rules» и «Gotchas». Самые
дорогие:

- `\b` в регулярках по кириллице **не работает** — границу задавать явно.
- Кириллица в собранном `main.js` — `\uXXXX` **верхним** регистром. Проверять
  только `node scripts/check_bundle_strings.mjs`.
- Источники править только редактором. Перезапись через PowerShell-пайплайн
  превращает файл в мусор.
- Файлы писать UTF-8 **без BOM**; после правки проверять первые три байта.
- Время в API — `RFC3339Nano`; любая запись в БД двигает `updated_at`.
- Стенд собирать с `CGO_ENABLED=0`; бинарь подменять только после сборки.
- **Экран не ходит в чужой сервис на каждый показ** — кеш + явная кнопка.
- **Кэш текста ключуется по всему, что видел модель**: данные КП, набор
  систем, карточка. Иначе текст молча замерзает.
- Коммит/пуш/деплой/выкладка — только по явной команде пользователя, на одну
  партию. «Продолжай», «ок» — не команда фиксировать.
