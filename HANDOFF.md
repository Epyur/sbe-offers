## Что в 0.9.20 (2026-11-13, R2): одна кнопка «Создать новый документ»

В меню вместо «🧾 Собрать КП» и «⚔️ Боевой листок» — одна кнопка
**«✨ Создать новый документ»**. Бот спрашивает вид (КП / листок), затем первым
делом — дословно по заявке — **«Какой продукт или систему вы хотите предложить
покупателю?»**. Название уходит в поиск по Базе знаний (`/bot/suggest`), найдённое
показывается нумерованным списком; номера — кнопки. Ничего не нашлось — не тупик:
«уточнить название» рядом с «выбрать в приложении». После выбора — развилка
**«📚 Собрать контекст в чате»** (существующий бриф) или **«📱 Продолжить в
приложении»** (создаётся строка документа, продукт записывается, ответ несёт
инлайновую `web_app`-кнопку на `#/offer/{id}` / `#/sheet/{id}`).

Старые подписи «Собрать КП» и «Боевой листок» остались **псевдонимами** в

## Исправление 2026-11-13 (после первого живого запуска): приложение не входило

Живая жалоба: в Telegram приложение показывало «initData: нет» и «Нет доступа:
войдите в бота…», хотя человек в бота входил.

**Причина — не в коде входа, а в странице.** `<script>` Telegram грузился с
`https://telegram.org/js/telegram-web-app.js`, а сервер (РФ) до `telegram.org`
не достаёт вовсе (`curl` с хоста: таймаут). Скрипт не загружался →
`window.Telegram.WebApp` не появлялось → `initData` пустой → приложение честно
писало «Открыто вне Telegram». Сам вход (`/app/session`, токен бота,
привязка чата) при этом исправен: сервер отвечает `400` на пустое тело,
`401` на неверную подпись, в `offers_bot_config` токен стоит, привязок 10.

**Что сделано:**
1. Скрипт Telegram теперь раздаётся **с нашего домена**:
   `offers-app/public/vendor/telegram-web-app.js` (в сборке —
   `dist/vendor/`), в `index.html` — `./vendor/telegram-web-app.js`.
   Правило: у приложения нет внешних зависимостей; CDN с этого хоста не
   достаётся.
2. Новая проверка **`scripts/check_app_browser.mjs <baseUrl>`** — смотрит на
   приложение снаружи так, как его видит человек: нет внешних скриптов, скрипт
   Telegram отдаётся с нашего домена и это действительно он, сборка совпадает
   с собранной, `/app/config` отвечает, вход с неверной подписью даёт `401`.
   Итог: **15 ок, 0 провалов**. Её место — рядом с `check_app_auth.mjs`.
3. Новый `index.html` выложен, sha256 сверен по https
   (`c02f18cb…`, скрипт Telegram `baa788a6…`).

## Второй живой дефект 2026-11-13: поиск в списках не находил ничего

Сначала стенд, потом боевая база — но оба раза одно и то же: «поиск не нашёл»,
хотя совпадения есть. Две разные причины:

1. **Порядок.** SQL брал свежие 200 строк, и только потом по ним шёл фильтр.
   Совпадения оказывались глубже — на стенде «Ромаш» есть в 19 строках, все
   глубже двухсот свежих. Теперь поиск просматривает `listScanLimit` (2000) и
   отдаёт первые `listLimit` (200); сторож —
   `TestSearchScansMoreThanItReturns`.
2. **Регистр.** `parseListQuery` приводил к нижнему регистру только SQL-шаблон,
   а проверка совпадения в памяти шла по запросу как его набрали. `lower()` базы
   зависит от локали, `lowerASCIIFree` — нет: «ромаш» находил 143 строки,
   «Ромаш» — ноль. Теперь запрос приводится один раз в разборе
   (`parseListQuery` → `lowerASCIIFree`), и SQL и память видят одно и то же.
   Сторож — `TestParseListQueryNormalises`, `TestContainsPatternIsSubstringTie`.

**Проверено на боевой базе** (`scripts/check_list_search_live.mjs`, через
контейнер node — на хосте node нет): «СтройМонтажСервис» — находит; строчными —
столько же; подстрока из середины («тройМонтажСерви») — находит; мусор — пустой
массив. **7 ок, 0 провалов.** Пробная строка `999/2026` заведена для проверки и

## Все живые исправления 2026-11-13 (после первого настоящего запуска)

Один день, пять дефектов, каждый — с живой жалобы. Все исправлены и
выложены; порядок ниже — в том, в каком их находили.

1. **Приложение показывало «initData: нет».** Две причины подряд:
   (а) `<script>` Telegram грузился с `telegram.org`, а сервер в РФ до него
   не достаёт — теперь скрипт раздаётся с нашего домена
   (`offers-app/public/vendor/telegram-web-app.js`); (б) мост к Telegram
   захватывался при загрузке модуля, и если скрипт опаздывал, приложение
   навсегда оставалось «вне Telegram» — теперь мост читается при каждом
   обращении и при старте ждёт до 2 с (`waitForTelegram`).
2. **У бота не было главного Mini App** (`has_main_web_app: false`), поэтому
   `web_app`-кнопки открывались как обычные ссылки без подписи. Настраивается
   только в BotFather (Menu Button → адрес приложения), из кода не делается.
3. **«Экран не найден» на первом экране.** Telegram дописывает в хэш свои
   параметры (`tgWebAppData`, `tgWebAppVersion`), и разбор маршрута принимал
   их за путь. Теперь параметры платформы отбрасываются, а `tgWebAppStartParam`
   уважается; тесты — на реальный хэш.
4. **Список КП падал с «db error» у всех, кроме владельца.** Условие
   видимости добавлялось как ` AND …` без проверки, есть ли `WHERE`: без
   поиска получалось `FROM offers_offer AND …` — синтаксическая ошибка.
   Владелец не видел (у него `superadmin`, ветка не выполняется), поэтому
   жалоба пришла от `fireservice@tn.ru`. Сторож — `lists_sql_test.go`.
   Живая проверка: `fireservice@tn.ru` → 200 (4 своих КП), владелец → 200 (20).
5. **Кнопка «📱 Открыть приложение» убрана из главного меню бота** (решение
   пользователя): reply-клавиатура с `web_app` открывала приложение без
   подписи. Приложение открывается из списков КП и листков, где кнопки

  Состав ссылается на материалы вики-ссылками `[[Название]]`; строки без
  ссылки и без кода — слои и работы, а не ошибки. Раздел показывает **кеш**;
  перечитать — «↻ Перечитать из Базы знаний». В одном КП систем может быть
  несколько (`Offer.systems`, порядок выбора).
- **Бот** — «Собрать КП» начинается с контекста (объект → адресат → сделка →
  системы → условия → позиции). Файл принимается на любом шаге.
- **Форма КП** — блоки: текст, заголовок, список, таблица, разрыв страницы,
  ссылки, текст по промту, картинка с обтеканием, сравнение систем; повторы
  «по каждой системе» и «по каждой позиции»; размещение (отступы, «с новой
  страницы», «не разрывать»). Загруженный `.docx`-макет вытесняет блоки.
- **Документ** — по блоку формы **или** по макету `.docx`; тексты систем
  берутся из `offers_system_text` (кэш, без вызова модели при экспорте);
  каждая система — своё описание, свои преимущества, своя нумерация слоёв с 1;
  вступление описывает **все** выбранные системы, а раздел «выбрано» в промпте
  называет каждую систему **названием из карточки** (0.9.2), а не «система №N.
- **Боевой листок (0.9.0, 2026-11-08)** — быстрая справка-сравнение нашего
  продукта (систем из КП) с продуктами конкурентов. Отдельная вкладка в
  сайдбаре («Боевой листок»), свой список и карточка. Наш продукт — из систем;
  конкурент — из папки Базы знаний «материалы и системы конкурентов» (кеш +
  «↻ Перечитать», раздел «Конкуренты», admin). Своя форма — **тот же
  конфигуратор, что у КП**, под режимом `combat` (`offers_form.mode='combat'`).
  Кнопка «Форма КП» переехала внутрь раздела КП (рядом с «Новое предложение»).
  Готовый листок **выгружается в DOCX** (кнопка «⬇ DOCX»): печать по форме
combat, обе стороны сравнения — карточками. **В боте (0.9.1, 2026-11-09):**
   пункт меню «⚔️ Боевой листок» собирает листок с номером, выбор сторон
   кнопками, «⬇ DOCX», «📂 Мои боевые листки». Ещё не сделано (следующая
   партия): приём файла/ссылки конкурента и критическое сравнение моделью.

## Правила, которые нельзя нарушать

Полный список — `sbe-offers/AGENTS.md`, разделы «Rules» и «Gotchas». Самые
дорогие:

- `\b` в регулярках по кириллице **не работает** — границу задавать явно.
- Кириллица в собранном `main.js` — `\uXXXX` **верхним** регистром. Проверять
  только `node scripts/check_bundle_strings.mjs`.
- Источники править только редактором. Перезапись через PowerShell-пайплайн
  превращает файл в мусор.
- Файлы писать UTF-8 **без BOM**; после правки проверять первые три байта.
- Время в API — `RFC3339Nano`; любая запись в БД двигает `updated_at`.
- Стенд собирать с `CGO_ENABLED=0`; бинарь подменять только после сборки.
- **Экран не ходит в чужой сервис на каждый показ** — кеш + явная кнопка.
- **Кэш текста ключуется по всему, что видел модель**: данные КП, набор
  систем, карточка. Иначе текст молча замерзает.
- Коммит/пуш/деплой/выкладка — только по явной команде пользователя, на одну
  партию. «Продолжай», «ок» — не команда фиксировать.

### Стенд с нуля (2026-11-12, стоило времени)

Проверенный порядок после перезагрузки машины или первого запуска.
Всё это выполняется из `sbe-offers/`:

```
docker compose -f docker-compose.local.yml up -d
# бинарь стенда СНАЧАЛА удалить, потом собрать (см. ниже)
docker cp offers-service/offers-stand offers-local-app:/mailers-offers
docker restart offers-local-app
```

**Грабли, на которые ушло время сегодня:**

1. **Сервис в compose зовётся `offers`, а не `app`.**
   `docker compose ... up -d --force-recreate app` падает с `no such service: app`.
   Полный список: `docker compose -f docker-compose.local.yml config --services`.
2. **`docker cp` в удалённый контейнер молча падает.** `docker cp ... offers-local-app:...`
   на несуществующем имени выводит `Error response from daemon: No such container`,
   а старый бинарь остаётся. После `docker rm -f` контейнер надо поднять заново.
3. **Старый `offers-stand` не перезаписывается молча, если уже существует.**
   `go build -o /src/offers-stand .` в контейнере может не перезаписать
   замоканный Windows-процессом файл и выйти с кодом 0.
   Поэтому **сначала `rm -f /src/offers-stand`**, потом сборка:
   `sh -c "rm -f /src/offers-stand && go build -o /src/offers-stand . && ls -l /src/offers-stand"`.
   Признак успеха - новое время в `ls -l`, а не только размер.
4. **Проверять бинарь в контейнере по `md5sum`, а не по размеру:**
   `docker exec offers-local-app md5sum /mailers-offers` против
   `(Get-FileHash offers-service/offers-stand -Algorithm MD5).Hash`. Размер совпадает
   у разных сборок, md5 - нет.
5. **403 на стенде может быть НЕ тем, о чём думаешь.** Роль выдаёт
   `auth-stub` по `AUTH_STUB_ROLES` (`owner@tn.ru=superadmin,manager@tn.ru=editor`), а
   `makeJwt('other@tn.ru')` даёт токен БЕЗ роли - `requirePerm("viewer")` отсекает
   до любой проверки видимости. Для проверки «чужой видит/не видит» берите
   **существующую роль** (`manager@tn.ru`), а не произвольный адрес.
6. **Вывод стенда в PowerShell приходит кракозябрами; иёт он кириллицей.**
   `Select-String` по такому выводу не находит ничего и выглядит как «тесты не запускались».
   Считать провалы так: сохранить вывод в файл и искать по последней строке
   «Итого: N ок, M провалов», или читать файл через `Get-Content -Encoding UTF8`.

## Как выкладывать выпуск

Порядок проверен на 0.7.6 … 0.8.2; подробности и грабли — в архиве.

1. **Версия и новость.** Поднять номер в `manifest.json` и `package.json`,
   **переписать текст новости ЦУП** в `src/main.ts` (`announceOnce`) и
   строки-иглы в `scripts/check_bundle_strings.mjs`, затем `npm run build`.
2. **Проверки** — полный прогон выше.
3. **Коммиты** на `backend` (сервис / стенд / выпуск — по смыслу) и пуш.
4. **Перенос на `main`**: `git checkout main`, `git checkout <release> -- main.js
   manifest.json styles.css src scripts package.json AGENTS.md HANDOFF.md`,
   `tsc`, коммит, пуш. Серверные папки в `main` **не переносятся**.
5. **Деплой**: `git archive --format=tar <release> offers-service offers-bot` →
   `scp` → `tar xf` в `/opt/mailers` → **сверить `md5sum` ДО сборки** →
   `docker compose build` → `up -d --force-recreate` → health `ok`, поллер.
6. **Самораздача**: `scp` трёх файлов в `/tmp/selfhost-upload/sbe-offers/`,
   сверить `sha256sum`, `kb-selfhost.sh sbe-offers`, затем скачать три файла по
   https и сверить суммы ещё раз.
7. **Реестр**: `www/registry.json` на сервере поправить **точечно по ключу**
   (`version`, `uploadedAt`, три суммы) — скрипт пишет только суммы. Затем
   git-копия `sbe-apstore-registry`, коммит и пуш.
8. **Документация**: `AGENTS.md` и `HANDOFF.md` — блок выпуска с хэшами;
   корневой `plugins/AGENTS.md` — строка таблицы версий; `check_docs_state`.

**Доступ к серверу:** алиас `epyur` из `~/.ssh/config` (ключ
`id_ed25519_20261103`); `scp`/`ssh` на голый адрес `root@176.12.69.109` даёт
`Permission denied (publickey)`.
