## 0.4.4 — «Добавить систему» не срабатывала (живая жалоба 2026-11-02)

Симптом от пользователя на КП 003: выбираешь систему в карточке КП, жмёшь
«Добавить» — Notice «Выберите систему», ничего не добавляется.

**Причина найдена и подтверждена на боевой базе:** ни одна из **375** живых
карточек `commercial_propose` не содержит `system_sku` (проверено SQL по
`notes.content_md` в `mailers-kb-db-1`; в кэше раздела — 375 систем, у всех
пустой `sku`). Плагин строил `<option value={system.sku || ''}>`, то есть
единственное значение всех вариантов — пустая строка; `if (!sku)` срабатывал
на любом выборе. Та же дыра была у бота (`system.sku` в `/bot/systems`) и на
сервере (`FindSystem` умел только код).

**Что сделано:** выбор системы несёт заметку Базы знаний.

- Сервер: `SystemChoice{SKU, NoteID}`, `SystemCard.Choice()/Handle()`,
  `ParseSystemChoice` (`sys-<id>` — заметка, иначе код; префикс не даёт
  спутать номер с кодом). `FindSystem` ищет по коду, затем по заметке.
  Ручки `POST /offers/{id}/system` и `POST /bot/offers/{id}/system` принимают
  `sku` или `noteId`; `/bot/systems` отдаёт `noteId`.
- Плагин: `<option value="sys-<noteId>">`, `offersService.addSystem(choice)`
  разбирает значение и шлёт `noteId`.
- Бот: `systemChoice()` — код, если есть, иначе заметка.
- Стенд: в `kb-stub` заведена карточка **без кода** (заметка 100) — на стенде
  этого случая не было вовсе, из-за чего дефект не воспроизводился (кэш систем
  там живёт в БД стенда — при правке стаба `delete from offers_context where
  mode='systems'` и `docker restart offers-local-kb-stub`).

Проверки: `go test` зелёный, `gofmt -l` пусто, `go vet` чисто; бот `tsc` +
**89 тестов**; плагин `tsc --noEmit` EXIT=0, `npm run build`,
`check_bundle_strings` 0 отсутствующих, OpenAPI 61/48; стенд **231/231**.

## Что за плагин

**LogicTEAM.КП** (`sbe-offers`) — коммерческие предложения для строительных
материалов. Менеджеры собирают КП в Telegram-боте, администратор настраивает
справочник и форму документа в плагине внутри Obsidian, на выходе — DOCX на
корпоративном бланке.

Вольт: `C:\Obsidian\mailers`. Папка плагина:
`.obsidian/plugins/sbe-offers`. Бэкенды живут **внутри** этой папки:
`offers-service/` (Go) и `offers-bot/` (Node). Ветка чекаута — `backend`.

## Что в системе сейчас (кратко)

- **Материалы** — то, что продаём: свой SKU (назначает сервер), варианты ЕКН,
  вилка цен. **Цены в справочнике нет** — цена приходит из таблицы менеджера.
- **Системы** — карточки БЗ с тегом `commercial_propose` без `material`. Состав
  ссылается на материалы вики-ссылками `[[Название]]`; непрописанные строки
  («Монолитная ЖБ Опора», «Уплотнённый грунт») — это слои, а не материалы.
  Раздел показывает **кеш**; перечитать — «↻ Перечитать из Базы знаний».
- **Бот** — «Собрать КП» начинается с контекста (объект → адресат → сделка →
  системы → условия → позиции). Файл принимается на любом шаге.
- **Форма КП** — блоки: текст, заголовок, список, таблица, разрыв страницы,
  ссылки, текст по промту, картинка с обтеканием + размещение.
- **Документ** — шапка из первого блока, позиции таблицей с ЕКН, итог, подпись.

## Правила, которые нельзя нарушать

Полный список — `sbe-offers/AGENTS.md`, «Rules» и «Gotchas». Самые дорогие:

- `\b` в регулярках по кириллице **не работает** — границу задавать явно.
- Кириллица в собранном `main.js` — `\uXXXX` **верхним** регистром. Проверять
  только `node scripts/check_bundle_strings.mjs`.
- Источники править только редактором. Перезапись через PowerShell-пайплайн
  превращает файл в мусор (логотип инцидента: `jsonrepair.go` → `Р Р°Р·Р±РѕСЂ`).
- Файлы писать UTF-8 **без BOM**; после правки проверять первые три байта.
- **`git show … | Set-Content` и любой пайплайн PowerShell над текстом** на
  этой машине периодически отдают **0 байт / пустые строки** (наблюдалось
  2026-11-02 на `AGENTS.md` и `offers_local_e2e.mjs`). Проверять результат
  через `python -c "len(open(...).read())"`, а перед коммитом — `git diff`.
- Время в API — `RFC3339Nano`; любая запись в БД двигает `updated_at`.
- Стенд собирать с `CGO_ENABLED=0`; бинарь подменять только после сборки.
- **Экран не ходит в чужой сервис на каждый показ** — кеш + явная кнопка.
- Коммит/пуш/деплой/выкладка — только по явной команде пользователя, на одну
  партию. «Продолжай», «ок» — не команда фиксировать.

## Что осталось из отчёта пользователя 2026-11-02

Отчёт был из четырёх пунктов; P0 (шапка документа) и P1 (ЕКН) сделаны.
Остались:

1. **«Добавить систему» не присоединяется (пункт 1, первая часть).**
   На стенде **не воспроизводится**: `POST /offers/{id}/system` берёт код из
   списка и дописывает состав; кеш и живой список дают те же 376 систем.
   **Нужен точный текст ошибки/Notice от пользователя** (и способ вставки:
   кнопка «➕ Добавить» или из карточки). Не править, пока его нет: уже дважды
   чинили не тот механизм. Гипотезы для проверки, когда текст будет: (а) часть
   систем в списке имеет пустой `sku` — тогда `value` опции `''` и кнопка
   молча выходит по `if (!sku)`; (б) `offerForEditor` требует владельца или
   admin — роль `editor` правки чужого КП получает 403.
2. **«Ошибки в составе» (пункт 1, вторая часть).** Систему это **не
   блокирует** — проверено на 373 живых карточках (1273 строки без ссылки, все
   — слои и общестроительные материалы). Надо переписать формулировку
   (`resolveComposition` в `systemcards.go`, `systems-editor.ts`): «слои без
   материала» вместо «ошибки в составе», и не помечать карточку красным.
3. **Макет КП с загрузкой .docx (пункт 2).** Не начато. Замысел: загрузить
   `.docx`-макет в «Форму КП», в нём плейсхолдеры (`{{object_name}}`,
   `{{manager}}`…) и метки мест вставки (`{{#блоки}}`, `{{#позиции}}`,
   `{{#по-системам}}`); сервис вставляет в макет, сохраняя стили бланка.
   Отдельное решение: **свой бланк vs корпоративный `standard.docx`**.
4. **Повторяемый блок формы «по системам» (пункт 2).** Не начато. Новый узел
   `repeat` с `source: 'systems'` и пиктограммой/шаблоном дочерних узлов:
   блок печатается один раз на каждую систему предложения (`cardsForOffer`).

**Порядок, который предложил бы я:** сначала пункт 1, если пользователь даст
текст ошибки (это ломает работу сейчас); затем пункт 2 (полчаса — снимает
